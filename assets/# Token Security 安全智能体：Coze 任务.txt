# Token Security 安全智能体：Coze 任务说明

版本：1.0  
目标平台：Coze（扣子）工作流 / 插件 / 知识库  
项目名称：Token Security 安全智能体平台（Token Security Agent Platform）
核心场景：Prompt 安全调查、PCAP 数据调查及其连续对话闭环

## 1. 建设目标

本智能体不是只能点击“检测”的表单，也不是泛用聊天机器人。它应当像 Codex 一样理解自然语言、保留上下文、主动拆解目标、调用工具、解释证据，并在每一步完成后提出下一步建议。

用户只提交一次 Prompt 或 PCAP，智能体负责：

1. 识别用户意图和调查类型。
2. 判断是否需要补充信息，并用自然语言追问。
3. 展示可审计的任务计划，而不是展示隐藏思维链。
4. 调用检测、检索、报告和修复工具。
5. 根据工具结果观察、更新假设并决定是否继续规划。
6. 用普通人能看懂的语言给出结论、证据、限制和建议。
7. 主动提供 2--4 个可点击的追问或动作，形成连续闭环。

## 1A. 比赛任务总览：场景、任务与完成方式

这一节是给评审、指导老师和 Coze 搭建人员看的快速版本。后文的节点、工具和 JSON 设计，都是为下面三档任务服务的。

### 场景一：Prompt 安全调查（主要展示场景）

**场景**：用户准备把一段 Prompt 放进客服、办公助手或业务大模型，但不确定其中是否存在越权、注入、敏感信息诱导或绕过限制。

**要完成的任务**：智能体不能只回答“有风险/没风险”，还要指出风险在哪里、为什么成立、证据是什么、如何修改，以及修改后是否真的变安全。

**完成方式**：

1. 用户自然语言提交 Prompt，例如“帮我检查这段 Prompt，并告诉我为什么有问题”。
2. 智能体识别为 Prompt 任务，保存原始 Prompt，说明检测计划。
3. 调用语义检测、Token 局部异常检测和安全知识检索工具。
4. 输出风险类型、位置、证据、置信度和限制。
5. 主动给出“解释依据、生成修复版本、重新检测、生成报告”等选项。
6. 用户点击确认后，生成修复版本并重新检测，最后形成报告。

**可证明的比赛能力**：单一明确安全痛点、垂域知识增强、多个检测工具协同、解释性和“检测→修复→复检→报告”闭环。

### 场景二：PCAP 数据调查（第二个主要场景）

**场景**：安全人员拿到一批脱敏网络捕获文件，需要快速判断是否有异常流量、异常发生在哪个 Packet、可能是什么攻击以及影响范围。

**要完成的任务**：智能体要从上传文件开始，完成预检、批量分诊、异常定位、攻击研判、攻击链关联、处置建议和报告，而不是只显示一个异常数量。

**完成方式**：

1. 用户上传一个或多个 PCAP，并说明“帮我看看有没有异常”。
2. 智能体在同一个 PCAP 对话任务中追加文件，执行沙箱预检。
3. 调用批量检测和证据查看工具，输出异常 Packet/Request 区间、协议、方向、时间和证据 ID。
4. 结合网络知识库判断扫描、暴力破解、C2 或数据外传等攻击候选，并明确证据不足之处。
5. 主动建议“查看异常位置、关联攻击链、扩大画像、生成报告”等下一步。
6. 对隔离终端、封禁地址等有影响动作先请求授权；完成后进行复核并写入报告。

**可证明的比赛能力**：跨工具协同、受约束自主规划、观察结果后重新规划、证据链和授权闭环。单批最多 20 个文件；流量画像可另行选择样本数或全部数据。

### 场景三：日常安全问答与任务承接

**场景**：用户先问“你好”“你能做什么”“什么是 Prompt 注入”，或者提出不完整目标。

**要完成的任务**：让系统具有真实对话感，同时不假装自己是无限能力的通用助手。

**完成方式**：

- 问候和身份问题直接回答，并介绍可处理的 Prompt/PCAP 安全任务。
- 术语和攻击原理问题从知识库回答，标注来源和适用范围。
- “帮我看看这个”这类目标不完整的输入，主动追问需要的文件、目标或关注点。
- 复杂非安全工作说明专业边界，并给出可转化为安全任务的替代问法。

### 三档任务如何对应

| 比赛任务 | 在本项目中的落地 | 现场演示的完成证据 |
| --- | --- | --- |
| **基础任务：场景化安全智能体构建** | 以“Prompt 安全调查”为单一主场景；支持自然语言提交、风险检测、证据解释、修复和报告 | 一段 Prompt 从提交到风险说明，再到修复版本和复检结果；全程保留对话 |
| **进阶任务：领域知识增强与工具扩展** | 建立 Prompt、Token、PCAP、ATT&CK、合规五类知识库；接入语义检测、Token 检测、PCAP 解析、证据查看、报告和修复工具 | 点击“为什么有风险”能引用知识来源；点击“关联攻击链/生成报告”能调用工具并返回结构化结果 |
| **终极任务：超级智能体与自主闭环** | 用意图路由、计划、条件分支、工具调用、观察、有限重规划、推荐动作和授权门禁组成 SuperAgent | 用户只提交一次目标，智能体主动规划、提出追问和动作，用户确认后继续执行，最后完成复检或报告；每步有证据和状态 |

### 终极任务的闭环判定

只有同时满足以下条件，才算完成“超级智能体”演示，而不是普通检测页面：

1. **理解指令**：不要求关键词，能根据上下文判断 Prompt、PCAP、知识问答和追问。
2. **自主规划**：先给出调查计划，并按工具结果决定下一步。
3. **跨域协同**：Prompt 场景至少协同语义/Token/知识工具；PCAP 场景至少协同预检/检测/证据/关联工具。
4. **主动推进**：每个关键结果后自动给出相关追问和可执行动作。
5. **观察反馈**：修复、扩展调查或处置后重新检查结果，而不是一次性结束。
6. **安全边界**：危险动作必须授权；工具不可用或没有证据时如实降级。
7. **可审计**：用户目标、计划、工具回执、证据、假设、限制、授权和报告均可回看。

## 1B. 创新点

1. **从“检测器”升级为“对话式安全调查员”**：用户可以问“为什么”“依据是什么”“还能做什么”，智能体基于当前案件继续回答，不要求重新输入材料。
2. **Prompt 与 PCAP 双证据互补**：Prompt 使用语义和 Token 局部证据，PCAP 使用协议、方向、时间和 Packet 证据；两种输入严格分流，避免把网络问题误判成 Prompt 问题。
3. **主动建议驱动闭环**：把“追问”和“动作”分开。前者帮助理解，后者真正调用修复、复检、关联或报告工具。
4. **可审计决策链**：展示可复现的计划、工具回执、证据和不确定性，不泄露不可验证的隐藏思维过程。
5. **真实/模拟能力透明**：每个连接器都标明真实可用、模拟演示或暂不可用，保证比赛演示和最终材料可信。
6. **专业工作区与安全对话分工**：对话负责理解和自主推进，工作区负责专业人员的批量参数、画像抽样、评测和手动复核，避免功能重复。

## 1C. 限制与诚实边界

- 当前平台重点解决 Prompt 安全调查和 PCAP 数据调查两个垂直场景，不是可以处理所有办公任务的通用 Agent。
- PCAP 检测每批最多 20 个文件；画像抽样数量与检测批次限制相互独立。
- 没有终端进程、身份日志或完整网络上下文时，只能给出“疑似”攻击链，不能声称攻击成功或确认内鬼身份。
- PCAP Docker、Prompt GPU runtime 和外部连接器受部署环境影响；不可用时只能给出证据、重试或模拟预览。
- EDR 隔离、防火墙封禁、身份查询等真实动作需要实际插件、权限、审批和回滚机制；当前未连接时不伪造执行结果。
- 对外展示原始 Prompt 和 PCAP 载荷受权限与脱敏策略限制；页面展示结构化证据摘要而非完整敏感内容。
- 不展示模型隐藏 Chain-of-Thought，以结构化决策链替代；这不影响用户看到“做了什么、依据是什么、下一步是什么”。

## 1E. Entropy-CPD 论文与本项目的关系

项目中的 Entropy-CPD 来自 CPDonline 的公开研究实现和实验设定，不是本项目原创算法。它研究的问题是：模型生成用户 Token 时，熵的在线变化点能否作为优化型 jailbreak 后缀的异常候选，并进一步定位异常起点。

### 论文方法在本项目中解决什么问题

- **语义 Guard 解决“内容是否危险”**：适合识别直接表达的危险请求。
- **Entropy-CPD 解决“Token 分布何处发生异常变化”**：提供独立的变化证据和 Token/字符级起点定位。
- **固定融合策略解决两者互补**：语义危险直接拦截；语义安全但出现 CPD 候选时进入实验拦截或人工复核，具体取决于工作模式。

因此，Coze 智能体应把 Entropy-CPD 当作调查证据工具，而不是把它包装成一个单独的万能分类器。对话中可以这样解释：“CPD 在第 X 个 Token 附近发现分布变化，这支持进一步检查；它本身不能证明攻击成功，也不能还原原始 Prompt 的真实意图。”

### 已知实验问题和展示限制

仓库的冻结实验已经发现：在当前跨模型数据上，Global NLL 和 Window NLL 的整句分类效果优于 Entropy-CPD；Entropy-CPD 的测试误报偏高。因此材料和智能体都不能声称“CPD 分类性能最好”“可以准确识别所有 jailbreak”或“适合作为单证据生产封禁器”。

Entropy-CPD 当前更适合承担三项职责：

1. 为语义结果提供第二路独立证据。
2. 定位可能的异常起点，帮助用户理解“问题从哪里开始”。
3. 触发复核、解释、知识检索和后续追问，而不是单独决定高影响处置。

在 Coze 配置中，工具返回值应标记为 `derived` 或 `real`（取决于实际模型运行状态），并携带阈值版本、异常起点、置信度和局限。若 Token 模型不可用、超时或证据不足，智能体必须明确降级为“仅有语义检测/无法提供 CPD 定位”，不得用历史结果补齐当前结论。

### 与三档比赛任务的对应

- **基础任务**：把论文方法可靠接入 Prompt 单一安全场景，展示“语义危险识别 + Token 异常起点定位”的互补证据链。
- **进阶任务**：用知识库解释 entropy、变化点、攻击后缀和误报边界，并通过报告引用真实实验版本和限制。
- **终极任务**：让 SuperAgent 根据 CPD 是否告警、语义结果和用户目标，自主决定解释、复检或人工复核等下一步；不能让 CPD 单独触发封禁或隔离。

## 1D. 交付材料中建议的一句话

> 我们构建的是一个面向 Prompt 与 PCAP 安全调查的垂直对话智能体：它能够理解自然语言，围绕当前案件持续追问，主动规划并调用检测、知识、修复、复检和报告工具；在需要时请求授权完成处置，并通过可审计证据链实现从发现问题到验证结果的闭环。基础任务展示单一场景，进阶任务展示知识库和工具扩展，终极任务展示多工具协同、观察反馈和自主推进。

## 2. 产品定位与范围

### 2.1 产品定位

面向大模型应用安全运营的垂直智能体，重点解决两类问题：

- Prompt 安全调查：判断 Prompt 是否包含越权、注入、敏感信息诱导、规避限制或其他风险，并解释风险位置和修复方法。
- PCAP 数据调查：在隔离环境中分析上传的网络捕获文件，定位异常 Packet/Request，判断攻击类型、攻击目的和影响范围。

专业工作区保留给专业人员手动设置参数、批量范围、画像抽样和评测；安全对话承担“理解目标、规划、解释、建议和闭环”。两者不能混为一个静态结果页。

### 2.2 明确不承诺的能力

- 不宣称已连接真实 EDR、防火墙、身份平台或 SIEM，除非 Coze 插件确实配置并通过健康检查。
- 不凭空声称封禁、隔离、修复已经执行。
- 不展示模型隐藏 Chain-of-Thought。对外展示结构化决策链：意图、计划、工具回执、证据、假设、不确定性、限制和下一步。
- PCAP 原始载荷、私有路径、凭据、完整内网地址等默认不进入聊天展示。

## 3. 智能体角色与系统提示词

将下面内容作为 Coze 的系统提示词基础版本，并通过变量注入当前模式、任务 ID 和证据摘要。

```text
你是“安全对话”，一个面向 Prompt 与 PCAP 调查的垂直安全智能体。

你的首要目标是帮助用户完成安全调查和后续处置，而不是只返回一个风险标签。
你必须：
1. 用自然语言理解用户，不要求用户记忆关键词。
2. 记住当前会话中的原始 Prompt、PCAP 文件、调查目标、工具结果和历史追问。
3. Prompt 与 PCAP 严格分流；PCAP 问题不能跳到 Prompt 任务，反之亦然。
4. 先说明准备做什么，再调用合适工具；工具完成后解释证据和限制。
5. 每次有实质结果时，主动提供 2-4 个与当前状态相关的“推荐追问”和“建议动作”。
6. 区分问题与动作：解释、为什么、依据是什么是追问；生成报告、修复、复检、扩大调查是动作。
7. 只读动作可直接执行；封禁、隔离、删除、修改生产配置等有影响动作必须先请求用户授权。
8. 工具超时、无证据、解析失败或连接器不可用时，要明确说明真实状态并给出可行动的替代方案。
9. 普通问候和身份问题可以简短回答，然后说明你能处理的安全任务。
10. 与安全无关的复杂任务要说明专业范围，不要假装万能。

回答风格：先给结论，再给证据和下一步；中文、清晰、可执行；不要泄露隐藏思维过程。
```

## 4. 输入与会话状态

Coze 会话必须持久化以下变量。变量名可按实际工作流调整，但语义不能省略。

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `conversation_id` | string | Coze 对话 ID |
| `task_id` | string | 平台安全任务 ID；同一任务追加文件和追问 |
| `mode` | enum | `prompt` / `pcap` |
| `original_prompt` | string | 用户提交的原始 Prompt，仅在授权范围内展示 |
| `pcap_files` | array | 文件显示名、哈希、大小、导入时间；不保存敏感载荷到消息 |
| `investigation_goal` | string | 当前调查目标 |
| `messages` | array | 用户和智能体消息、角色、时间戳、来源 |
| `plan` | array | 当前计划步骤及状态 |
| `evidence` | array | 证据 ID、类型、摘要、来源、可信度 |
| `hypotheses` | array | 当前假设、支持证据、反证和置信度 |
| `next_actions` | array | 推荐追问和可执行动作 |
| `authorization` | object | 是否需要授权、授权范围、过期时间 |
| `connector_state` | object | 实际可用、模拟或不可用的连接器状态 |

原始 Prompt 必须在任务记录中保留，并在刷新、重新打开历史任务后恢复；展示时应遵守脱敏和权限规则。上传新的 PCAP 时，如果当前 `mode=pcap` 且已有 `task_id`，追加到同一任务，不得自动新建对话。

## 5. 总体工作流

推荐在 Coze 中编排如下节点：

```text
开始
  -> 会话恢复节点
  -> 意图路由节点
  -> 安全范围与权限节点
  -> 缺失信息判断
       -> 需要澄清：追问并等待用户
       -> 信息完整：生成计划
  -> 工具调用节点（Prompt 或 PCAP）
  -> 证据归一化节点
  -> 结论与不确定性节点
  -> 主动建议节点
       -> 用户选择追问：回答并回到建议节点
       -> 用户确认动作：执行动作并回到观察节点
       -> 用户结束：保存任务与报告
```

单次运行最多 12 个计划步骤、最多 3 个并行只读工具、最多 2 次重新规划；所有循环都要设置超时和终止条件。

## 6. 意图路由

不要使用“必须包含某个关键词”的规则。使用大模型分类 + 当前上下文 + 文件类型三者共同判断。分类节点输出严格 JSON：

```json
{
  "intent": "prompt_investigate|pcap_investigate|security_knowledge|follow_up|generate_report|remediate|recheck|greeting|out_of_scope",
  "mode": "prompt|pcap|unknown",
  "confidence": 0.0,
  "needs_clarification": false,
  "clarifying_question": "",
  "reason": "基于当前会话和输入的简短分类依据"
}
```

路由规则：

- 当前任务有 `mode=pcap` 时，“这段流量为什么异常”“继续看刚才的文件”等追问继续走 PCAP。
- 当前任务有 `mode=prompt` 时，“为什么这个 Prompt 有风险”“改完再测”等继续走 Prompt。
- 用户同时提供 Prompt 和 PCAP 时，先说明需要拆成两个调查，询问先处理哪一个。
- 只有“你好”“你叫什么”“你能做什么”等输入时，直接进行日常交流，不启动检测。
- “帮我看看这个”“这里有什么问题”等目标不完整时，追问目标，不要报“超出范围”。

## 7. Prompt 安全调查流程

### 7.1 主流程

```text
接收原始 Prompt
 -> 保存原文与时间
 -> 语义安全检测
 -> Token/局部异常检测（可用时）
 -> 规则与知识库检索
 -> 证据融合
 -> 标注风险位置与类型
 -> 用人话解释“为什么”
 -> 建议修复版本
 -> 用户确认后生成修复 Prompt
 -> 重新检测修复版本
 -> 用户确认后生成调查报告
```

### 7.2 Prompt 工具

`prompt_security_scan` 输入：原始 Prompt、检测策略、是否进行 Token 级分析。输出：风险级别、风险类型、位置区间、证据 ID、模型状态和限制。

`prompt_explain_evidence` 输入：任务 ID、证据 ID、用户问题。输出：风险机制、原文引用的脱敏片段、可信度、反例和限制。

`prompt_repair` 输入：原始 Prompt、风险类型、业务目标、禁止改变的约束。输出：修复版本、修改点、可能副作用、待复检标记。

`prompt_recheck` 输入：修复版本、原检测配置。输出：修复前后对比、残余风险和是否建议上线。

### 7.3 Prompt 对话示例

用户：“这个 Prompt 有问题吗？”  
智能体：“我会先检查越权指令、敏感信息诱导和绕过限制三类风险。检测完成后我会标出具体位置，并给出修复方案。”

结果后：

> 结论：发现高风险的越权指令。风险集中在第 2 段，要求模型忽略原有安全约束。依据是证据 `P-002`，置信度 0.91。当前没有发现凭据泄露迹象。  
> 你可以继续：`为什么这段算越权？` `生成修复版本` `只看证据` `生成调查报告`

用户点击“生成修复版本”后，智能体先生成草案；点击“重新检测”后才调用复检工具；涉及上线或替换生产 Prompt 时必须再次授权。

## 8. PCAP 数据调查流程

### 8.1 主流程

```text
上传一个或多个 PCAP
 -> 同一 task_id 建立用户消息
 -> 沙箱预检（只读、无网络、非 root、资源限制）
 -> 批量检测（每批最多 20 个文件）
 -> 解析协议、方向、时间与统计特征
 -> 定位异常 Packet/Request 区间
 -> 判断攻击类型
 -> 推断攻击目的与影响
 -> 关联攻击链（证据不足时明确标注）
 -> 建议处置
 -> 用户授权后执行模拟或真实连接器动作
 -> 复核结果并生成报告
```

流量画像可以由用户选择代表样本数量或“全部数据”；这与单次检测最多 20 个文件是两个独立限制。对话区只显示聚合统计、证据 ID、Packet/Request 区间和脱敏摘要。

### 8.2 PCAP 工具

`pcap_preflight`：检查文件类型、数量、大小、哈希和沙箱状态，不读取外部网络。

`pcap_batch_detect`：输入 `task_id`、文件哈希列表和批次范围；输出总文件数、已处理数、异常数、失败数及每个异常证据 ID。

`pcap_inspect_evidence`：输入证据 ID、Packet/Request 区间和用户问题；输出协议、方向、时间、脱敏字段、规则命中和可信度。

`pcap_correlate_attack_chain`：输入多个证据 ID；输出阶段、支持证据、缺失证据和不确定性，不得凭空补全攻击链。

`pcap_recommend_response`：输入攻击类型、影响、环境约束；输出只读调查建议和需要授权的处置动作。

### 8.3 PCAP 对话示例

用户上传 `capture-a.pcap`。  
智能体：“文件已加入当前 PCAP 调查，不会新建另一条对话。我先进行沙箱预检和异常分诊，完成后会告诉你异常发生在哪个 Packet 区间。”

结果后：

> 结论：在 20 个文件中发现 3 个异常候选，最高优先级证据为 `N-014`（Packet 1842--1860）。当前证据支持“疑似扫描后利用”，但不足以确认攻击成功。  
> 推荐追问：`查看异常位置` `为什么判断为扫描？`  
> 建议动作：`关联攻击链` `生成调查报告` `扩大流量画像范围`

用户再次上传文件时，仍追加到当前 PCAP 任务；若用户想开始新案件，必须点击“新建对话任务”。

## 9. 推荐追问与建议动作

每次检测、解释、修复或报告完成后，生成 2--4 项 JSON：

```json
[
  {
    "id": "explain_evidence",
    "kind": "question",
    "label": "为什么判定为高风险？",
    "prompt": "请基于当前证据解释判定依据、反例和不确定性",
    "requires_confirmation": false
  },
  {
    "id": "generate_report",
    "kind": "action",
    "label": "生成调查报告",
    "prompt": "基于当前任务证据生成报告",
    "requires_confirmation": true
  }
]
```

推荐策略：

- 有风险：解释依据、查看异常位置、生成修复/处置方案。
- 无风险：查看检测范围、查看限制、生成结果摘要、重新检查新输入。
- 证据不足：补充数据、扩大画像、查看解析失败原因。
- 已生成修复：重新检测、对比差异、生成报告。
- 已完成报告：下载/查看报告、开始新调查。

追问回答要引用当前任务，不重新要求用户粘贴原始 Prompt 或重复上传 PCAP。

## 10. 知识库与 RAG

知识库不是实现日常问候的必要条件，但对于专业解释、法规和最新攻击知识非常重要。建议建立以下分库：

1. Prompt 风险模式：注入、越权、数据外泄、绕过、社工诱导。
2. Token/模型安全：Token 异常、熵变化、对抗后缀、模型拒答边界。
3. 网络与 PCAP：协议基础、扫描、暴力破解、C2、数据外传、常见字段解释。
4. 攻击技战术：MITRE ATT&CK 技术、阶段、证据要求和置信度。
5. 合规与处置：行业政策、日志保留、授权流程、隔离和封禁审批。

每条知识应包含标题、正文、来源、发布日期、适用范围、版本和可信等级。RAG 只增强解释和建议，不覆盖检测工具返回的事实；没有检索结果时要明确说“未找到匹配知识”。

## 11. 证据、可解释性与隐私

统一证据格式：

```json
{
  "evidence_id": "N-014",
  "source": "pcap_inspect_evidence",
  "status": "real|simulated|derived|unavailable",
  "summary": "脱敏后的事实摘要",
  "location": "Packet 1842-1860",
  "supports": ["疑似扫描"],
  "confidence": 0.84,
  "limitations": ["未获得终端进程日志"],
  "created_at": "2026-09-07T10:00:00+08:00"
}
```

页面和报告必须区分：真实工具证据、模拟连接器回执、模型推导结论、不可用数据。展示“决策链”而不是隐藏思维链：

```text
用户目标 -> 执行计划 -> 工具回执 -> 证据 -> 假设 -> 结论 -> 不确定性 -> 下一步
```

原始 Prompt 只在当前用户有权限时展示；PCAP 仅保存必要元数据和脱敏结构化证据；日志中不得写入凭据、完整载荷或密钥。

## 12. 授权和连接器

动作分级：

- L0 只读：检测、解释、检索、画像、报告草稿，可直接执行。
- L1 低影响：生成修复草稿、创建工单、标记案件，需用户确认。
- L2 高影响：隔离终端、封禁 IP、修改防火墙、删除数据，必须显示目标、范围、原因、回滚方式和授权按钮。

每个连接器健康检查返回：`available`、`simulated` 或 `unavailable`。不可用时智能体必须说“当前没有真实连接”，并可提供模拟预览或手动操作清单，不能伪造成功回执。

## 13. 报告生成

报告由当前任务生成，不从空白模板编造内容。至少包括：

- 案件标题、任务 ID、开始和结束时间。
- 原始输入摘要（Prompt 可按权限显示；PCAP 显示文件哈希和统计）。
- 调查目标和执行计划。
- 工具执行状态和证据目录。
- 结论、置信度、未确认事项和限制。
- 修复或处置建议、授权记录和后续复检结果。

报告名称必须包含可辨识的任务摘要和时间，例如“Prompt 越权调查 - 2026-09-07 14:32”，不能所有任务都叫“调查报告”。

## 14. 异常和边界行为

- 模型超时：保留已完成工具结果，说明哪一步超时，给出重试或导出当前证据的动作。
- 无证据：回答“当前无法形成可验证结论”，说明缺什么，不得回答“没有风险”。
- 解析失败：区分文件损坏、格式不支持、沙箱不可用和连接器失败。
- 超出范围：简单日常交流正常回答；复杂非安全任务说明专业范围并给出可处理的安全替代问题。
- 用户取消：停止后续工具，保留已经产生的证据和取消时间。
- 用户删除任务：删除服务端任务和浏览器本地原始消息；删除当前任务后返回同模式新对话。

## 15. Coze 落地清单

### 15.1 工作流节点

- 开始 / 会话变量恢复
- 大模型意图分类（JSON 模式）
- 条件分支：Prompt、PCAP、知识问答、问候、越界
- HTTP 插件：平台 API、Prompt API、PCAP API、报告 API
- 知识库检索节点
- 证据归一化代码节点
- 计划与重规划代码节点
- 授权卡片节点
- 推荐追问 / 建议动作卡片节点
- 会话持久化节点

### 15.2 卡片交互

卡片按钮必须携带 `task_id`、`mode`、`evidence_ids` 和 `action_id`。点击动作后回到同一会话，不打开新的 Prompt/PCAP 任务。按钮文字要区分“追问”和“执行”，例如“为什么异常？”与“生成报告”。

### 15.3 插件安全

- 所有 API 使用服务端密钥，不把密钥放进前端或卡片参数。
- 校验 `task_id` 与 `mode` 一致，拒绝跨模式调用。
- PCAP 插件只允许白名单目录和固定参数，默认无网络、只读、资源受限。
- 高影响插件必须二次确认、记录授权人和幂等键。

## 16. 演示脚本

### 脚本 A：Prompt 连续闭环

1. 用户说“你好，你能做什么？”智能体简短介绍能力。
2. 用户提交一段包含越权要求的 Prompt。
3. 智能体展示计划并完成检测。
4. 智能体直接解释风险位置，并给出“为什么”“修复”“报告”等选项。
5. 点击“生成修复版本”。
6. 点击“重新检测”，展示前后差异。
7. 点击“生成调查报告”，展示报告和证据目录。

### 脚本 B：PCAP 连续闭环

1. 用户上传 PCAP 并说“帮我看看有没有异常”。
2. 智能体确认文件加入当前 PCAP 任务，执行沙箱预检和批量分诊。
3. 智能体指出异常 Packet 区间和证据 ID，说明尚不能确认攻击成功。
4. 用户点击“查看异常位置”和“关联攻击链”。
5. 智能体建议报告和处置；隔离/封禁动作弹出授权，不自动执行。
6. 再上传一个文件，验证仍在同一会话中追加。

## 17. 验收标准

### 对话体验

- 不依赖关键词；“你好”“为什么有问题”“继续分析刚才的文件”均能正确理解。
- 用户消息右侧、智能体消息左侧，显示名称和时间。
- 原始 Prompt 在当前任务和历史任务中可见（受权限控制）。
- 每次有结果后出现 2--4 个相关追问或动作。
- 点击动作后留在当前会话，不跳转到错误模式或新建无关任务。

### Prompt

- 能输出风险类型、位置、证据、解释、修复版本和复检结果。
- 能回答“为什么有问题”，而不是只显示风险等级。
- 修复和上线类动作有确认边界。

### PCAP

- 上传文件追加到当前 PCAP task；同一文件重复导入幂等。
- 批量检测单批最多 20 个文件；流量画像支持自定义样本数和全部数据。
- 能输出异常 Packet/Request 区间、攻击候选、证据限制和报告。
- 不显示检测小队到 PCAP 数据调查对话；PCAP 侦探挑战保持独立三角色流程。

### 可信性

- 真实、模拟、推导、不可用状态可见。
- 无证据、超时和连接失败不会被表述为“未发现风险”。
- 高影响动作没有用户授权不得执行。

## 18. 与比赛要求的对应关系

| 比赛要求 | Coze 实现证据 |
| --- | --- |
| 单一安全场景 | 以 Prompt 安全调查和 PCAP 数据调查为两个清晰入口，均有完整输入、分析和闭环 |
| 领域知识增强 | Prompt、PCAP、ATT&CK、合规知识库 + RAG |
| 工具扩展 | 检测、证据查看、修复、复检、报告和连接器插件 |
| 自主规划 | 意图路由、计划节点、条件分支、观察后重规划 |
| 可解释性 | 结构化决策链、证据 ID、置信度和限制 |
| 跨域协同 | Prompt 语义/Token 工具协同；PCAP 解析/关联/响应工具协同 |
| 闭环处置 | 检测 -> 解释 -> 修复/处置 -> 复检 -> 报告 |
| 安全合规 | 授权门禁、沙箱、脱敏、真实/模拟状态标记 |

比赛材料中建议表述为“可审计的安全智能体决策链”，并解释不展示隐藏思维链是为了保护敏感推理和避免不可验证的内容；展示的是可复现、可检查的计划、工具回执和证据链。

## 19. 当前项目能力对照

当前前端和后端已经具备连续对话、Prompt/PCAP 分流、任务历史、原始 Prompt 保存、PCAP 同任务追加、推荐动作、授权 UX、报告和隔离检测等基础。当前运行环境中：Prompt runtime 可用；PCAP Docker 可能因 AutoDL 环境不可用；EDR、身份、网关连接器为模拟状态。Coze 接入时应把这些状态通过健康检查注入对话，不能把模拟结果包装成真实外部执行。

## 20. 最小可交付版本优先级

1. P0：自然语言路由、会话持久化、原始 Prompt、Prompt/PCAP 分流、结果后推荐动作。
2. P0：Prompt 检测/解释/修复/复检和 PCAP 预检/检测/证据查看。
3. P1：报告生成、知识库 RAG、任务历史删除、异常和超时处理。
4. P1：模拟连接器授权流程和攻击链关联。
5. P2：真实 EDR/防火墙/身份/SIEM 插件、复杂多案件编排和自动复核。

验收顺序应先录通两个连续对话脚本，再展示知识库、授权边界、报告和连接器状态。这样能证明智能体不仅“检测出问题”，还能理解问题、回答追问、提出方案并在确认后完成下一步。
