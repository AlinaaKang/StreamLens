# StreamLens 明鉴 平台设计文档

**参赛方向**：AI 安全智能体 · Token 与网络流量异常检测
**项目名称**：StreamLens 明鉴——Prompt 与 PCAP 双轨安全调查智能体

---

## 1 项目概述

### 1.1 背景与问题

大模型应用落地后，Prompt 注入、越权指令、角色扮演绕过、敏感信息诱导泄露等攻击成为新的应用入口风险；传统网络侧又长期存在告警量大、证据分散、研判和报告依赖人工的问题。现有检测手段存在三类典型困境：

- **纯规则/纯语义路线**：规则引擎维护成本高、易被改写绕过；语义模型判断效果好但属于"黑盒结论"，无法解释、无法审计，误报时用户无从申辩。
- **单证据定罪**：仅凭单一信号（如统计异常、关键词命中）直接处置，误报率高，难以在生产环境立足。
- **流量告警与处置割裂**：PCAP 规则往往只输出标签，缺少包级定位、行为佐证、攻击链关联和可追问解释。

### 1.2 设计目标

构建一个**自然语言驱动、本地安全引擎执行、全程可审计**的双轨安全智能体：

1. 语义层（LLM 推理）与分布层（Entropy-CPD 统计检测）**独立取证、互不覆盖**；
2. 处置动作来自**固定融合表**，同一输入永远得到同一处置，可复核、可回归；
3. 每一条检测输出**结构化证据链**（real=真实检测 / derived=数学推导），处置决策步骤化展示，不包含隐藏思维链；
4. 配套**红蓝攻防演练**与**曲线侦探挑战**，让检测能力可被对抗验证、可被教学理解。
5. 对 PCAP 同时提供规则路、行为路和融合路，输出包级证据与攻击链候选，并明确未知攻击和加密内容的能力边界；
6. 由大模型负责理解、规划和解释，由本地引擎负责检测与证据生成，普通聊天、Prompt 检测、PCAP 调查通过显式模式路由分流。

```
└──────────────────────────────┬─────────────────────────────────────────────┘
                               │ REST / SSE 流式
┌──────────────────────────────▼─────────────────────────────────────────────┐
│                        FastAPI 服务层（main.py 路由）                        │
│   /api/prompt/analyze   /api/adversary/*   /api/tasks/*   /api/challenge/*  │
├────────────────────────────────────────────────────────────────────────────┤
│                            检测引擎（tools/）                                │
│  Prompt：规则标记 + Entropy-CPD + 语义扫描                                │
│  PCAP：规则路 + 行为统计路 + 融合路                                        │
├────────────────────────────────────────────────────────────────────────────┤
│   融合策略（固定融合表） → 风险分级 → 处置动作（放行/人工复核/拦截）           │
├────────────────────────────────────────────────────────────────────────────┤
│  证据与审计存储（case_store）：任务/消息/证据/审计事件；知识库（18 条已就绪） │
└────────────────────────────────────────────────────────────────────────────┘
```

- **前端**：单页应用，提供安全对话、Prompt/PCAP 专业分析、攻防实验、侦探挑战和审计任务等工作区。Token 风险轨道提供逐 token 的 z 值/累计统计可视化，PCAP 页面展示 Packet 证据和攻击链候选。
- **服务层**：FastAPI，同步检测与流式对话（SSE）统一出口；面板检测与对话检测共用同一条分析链路（`run_prompt_analysis`），保证口径一致。
- **存储**：任务（task）为中心的 case_store，消息、证据、审计事件按任务归档，支撑回溯、报告生成与审计复核。

## 3 核心检测设计：三路独立取证

### 3.1 第一路：规则标记层（marker_scan）

- 已知越权/绕过短语库匹配（如"忽略之前的所有指令"、角色扮演诱导模板等）；
- 定位：**快速通道证据**，命中仅作为证据入链，**不直接改变风险档位**（对齐"规则不单独定罪"原则）；
- 输出：命中短语、字符位置、上下文片段，置信 0.7，附限制说明"规则命中不代表实际攻击意图"。

### 3.2 第二路：Entropy-CPD 分布层（核心自研）

对输入文本构建 token 级统计轨迹，检测**分布突变**——注入拼接、载荷插入、高熵编码片段都会在熵轨迹上留下可度量的"台阶"。

**信号构建**：
- 字符级熵代理（无本地 LM token 熵的部署约束下，以字符频率 + 字符语言模型近似 token 熵）；
- 逐 token 计算 NLL（负对数似然），相对基线（char_freq / charlm 校准，`baseline_source` 字段记录来源）得到标准化偏离 **z 值**（保留符号：up=熵骤升·载荷突变候选；down=熵骤降·模板化片段参考）。

**在线变点检测（CUSUM）**：
- 维护累计统计量 W_t，超过报警门限 h 触发报警，输出首个报警点及后续 W 局部峰（最多 3 个候选）；
- **强突变直报通道**：单点 |z| ≥ 3.95 且其后邻域均值 ≥ 1.2 时无需累计满门限即可报警——针对"短促而强"的优化后缀攻击；
- 报警后三重校验（防误报核心，见 3.5）；
- 次候选：无报警但 |z| ≥ 2 的 token，置信上限 0.45（**观察级，不驱动处置**）；
- 兜底定位：无任何超阈信号时取 |z| 最大点作低置信锚点，保证每条检测都有 Token 锚点（便于教学与回放）。

### 3.3 第三路：语义扫描层（LLM）

- 内置大模型对待检 Prompt 做**意图与风险类别判定**，输出三档：safe / controversial / unsafe（异常时 unavailable）；
- 判定结果为 real 证据，附置信度与风险类别（注入、越权、泄露等），并明示限制"语义判断基于模型推理，存在误报可能"。

### 3.4 固定融合策略表

| 语义判定 | CPD 信号 | 风险级别 | 处置动作 |
|---|---|---|---|
| unsafe | 任意 | high | **拦截** |
| controversial | 任意 | medium | 人工复核 |
| unavailable（语义故障） | 任意 | gateway: medium / analysis: 放行(降级) | 人工复核（fail-safe）/ 放行并标注降级 |
| safe | alarm 级（conf ≥ 0.5） | medium | **人工复核**（纯统计异常不拦截） |
| safe | 观察级 / 无 | none | 放行 |

设计原则：

1. **拦截必须要有语义佐证**；CPD 属间接统计证据（其自身 limitations 声明"不能单独触发高影响处置"），语义安全时即使 CPD 报警也只转人工复核；
2. **不确定时不阻断**：语义服务故障时网关场景 fail-safe 转人工，分析场景降级放行并如实标注；
3. 融合表为固定策略（`fixed_fusion` 步骤），决策轨迹可复现、可回归。

**语义锚定交互升级**：语义判定异常（unsafe/controversial）时，若分布层存在观察级候选，将其升级为 alarm 级证据（`cpd_anchor=semantic_anchored`）——双证据交叉确认，解决英文对抗段在中文基线下呈负向突变、单向检测漏报的问题。

### 3.5 防误报机制（分布层四重闸门）

| 闸门 | 规则 | 针对的误报形态 |
|---|---|---|
| 短序列不报警 | token 数 < 10 不做报警判定 | 短文本统计不稳，自然波动当突变 |
| 持续偏移校验 | 报警点后 6 token 均值 ≥ 0.3 才成立 | 零星高 NLL（标点/罕见字）后迅速回落 |
| 强度校验 | 报警点 \|z\| < 2.0 → 拒绝报警（weak_step_amplitude） | 口语化短文的持续小幅正偏移（实测 \|z\|≈1.3~1.7 即可累计满门限，与真突变 \|z\|≈4.0 差一个数量级） |
| 短文本置信折减 | token 数 < 30 报警置信上限压至 0.45 | 短序列尾部偏移无回落窗口可校验 |

**真实案例**（误报治理前后）："光合作用是植物、藻类利用光能合成有机物的过程，请给小学生简单讲解"（32 字符）与"我曾经是一个很爱学习的人……"（37 字符）两条日常文本，修复前被误判高风险拦截；修复后强度校验拒绝报警（conf 0.3/0.43），融合处置为**放行，风险分 0**，而真攻击样本（GCG-02，|z|=4.0）与注入窃取样本仍被准确拦截——29 个挑战样本回归 **benign 零误报、attack 召回零损失**。

### 3.6 反事实归因（Counterfactual）

对存在预测起点的检测，将文本**截断至异常起点后重算 CPD**，对比分布分数变化：

- `risk_reduced`：移除定位片段后异常下降，归因成立；
- `unchanged`：证据冲突，需人工研判；
- 无预测起点时如实标注"不适用"（no_predicted_onset），不伪造结论。

## 4 可审计与证据链设计

1. **证据分级**：`real`=真实检测（语义判定、规则命中）、`derived`=数学推导（熵轨迹、CPD 候选、置信度），证据卡展示来源、状态、摘要、置信度、定位（字符区间）、snippet 与限制说明；
2. **决策轨迹步骤化**：系统只展示观察、工具调用、证据融合和处置结论等可审计记录，不输出或伪造模型的隐藏思维链；
3. **审计事件**：每次检测记录文本摘要、风险级别、处置动作与证据引用；发现疑似异常时处置口径为"**待授权复核**"（检测不越权执行处置），无发现为"放行"——杜绝"报告疑似、审计放行"的口径矛盾；
4. **全链留痕**：任务/消息/证据/审计事件按任务归档，支撑正式报告生成（Markdown/文档导出）与事后回溯。

## 5 功能模块

### 5.1 Prompt 安全分析面板

- 自定义输入 / 冻结测试样本两种模式；知识增强模式三档（关闭 / 仅证据 / 证据与报告）；
- 检测结论卡：语义安全、Token 分布（含 CPD 置信、异常起点）、融合处置（风险分数 x/1.0）；
- **Token 风险轨道**：逐 token 轨迹可视化，鼠标竖虚线吸附 + 顶端 T 序号标签，候选点高亮，点击选取异常起点——检测过程"看得见"；
- 一键"转对话修复复检"与"生成正式报告"。

### 5.2 对话式安全检测

输入框提供 Prompt 检测和 PCAP 检测模式。显式选择检测模式或明确提出检测请求时调用对应工具；普通聊天不因内容看似可疑而自动触发检测。已有案件中的自然语言追问优先读取当前证据和历史消息回答。结论卡片、工具状态和证据明细通过 SSE 流式回显；切换页面或刷新后可从任务记录恢复消息、证据和工具日志。

### 5.3 PCAP 调查

- 预检文件格式、大小和哈希，逐包解析协议、方向、时间、连接及载荷特征；
- 规则路覆盖端口扫描、SSH 暴力破解、C2 心跳、数据外传、SQL 注入、DNS 隧道、Web 攻击载荷、SYN 洪泛和 ARP 欺骗九类候选；
- 行为路根据端口广度、连接速率、时间间隔周期性、上行字节、DNS 标签等统计特征生成独立候选；
- 融合路归并同类同主体证据，保留来源路线、置信度、时间范围和包号定位，不预设融合一定优于单路；
- 0day、加密内容解密和完整 APT 渗透链不属于已验证覆盖范围。

### 5.4 红蓝攻防演练

- **红队**：编写攻击 payload 提交**真实检测引擎**，以是否拦截/检出计分；
- **蓝队**：对随机抽取样本做"正常内容/恶意攻击 + 风险级别"研判，与样本真值（归一化对齐 benign/normal 口径）比对计分；
- 回合制对战，回合详情中文化（"蓝队判 正常内容/未发现 · 真值 恶意攻击/高风险 · 引擎判定"），错误判定自动给对方加分。

### 5.5 曲线侦探挑战

以关卡制教学化呈现 CPD 检测能力：8 个样本族（SAFE 正常 / SHIFT 语义漂移 / AD 注入 / GCG 优化后缀 / ADVP 对抗后缀 / ENC 高熵编码 / CTX 上下文操纵 / EXF 数据外传），玩家观察 CPD 曲线与候选点定位异常起点，系统以反事实复检验证归因，评分并讲解。

### 5.6 审计中心

审计事件流水、风险分布、处置动作统计，支持按任务回溯完整证据链。

## 6 关键工程决策记录

| 决策 | 备选方案 | 选择理由 |
|---|---|---|
| 熵代理用字符级近似 | 部署本地 LM 取 token 熵 | 免 GPU、毫秒级延迟，满足在线检测；粒度限制写入 limitations 如实披露 |
| CPD 报警设三重校验 | 单一阈值 | 生产误报率优先；口语短文零星波动与真实突变可分离 |
| 语义 safe + CPD 报警 → 人工复核 | 直接拦截 | CPD 为间接证据，不能单独定罪；不确定不阻断 |
| 固定融合表而非模型融合 | LLM 自由决定处置 | 给定相同结构化证据时，融合逻辑可审计、可回归 |
| 处置动作"待授权复核" | 检测直接阻断 | 检测与处置职责分离，避免检测组件越权 |
| 蓝队真值归一化（benign→normal） | 字符串直接比对 | 消除样本库与提交口径不一致导致的误判 |

## 7 部署与运行

- 环境：Python 3.12，FastAPI + 单页前端，大模型通过 OpenAI 兼容接口配置；
- 启动：`python src/main.py -m http -p 5000`，浏览器访问 `/web`；
- Agent 默认配置为 `glm-5-0-260211`；Prompt 语义扫描代码当前指定 `qwen-3-5-plus-260215`，均以实际兼容网关和凭据为准；
- Entropy-CPD 与 PCAP 本地检测运行于 CPU。端到端耗时受模型服务、文件大小和网络环境影响，不承诺固定时延。
