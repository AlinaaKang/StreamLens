# StreamLens 明鉴 项目总结报告

## 一、项目背景

大模型正在成为业务入口，但它同时引入了 Prompt 注入、越狱、角色包装、编码载荷和多轮上下文操纵等新型风险。此类攻击常被改写或伪装，单纯关键词规则容易漏检，单一大模型判断又缺少可复核证据。

网络安全运营侧也存在长期问题：PCAP 或告警通常只给出“疑似异常”标签，分析人员还要手工查包、定位主机、关联攻击阶段并编写报告。若直接让大模型生成安全结论，还可能出现证据不足、能力夸大或处置越权。

StreamLens 明鉴因此把大模型应用侧的 Prompt 风险与网络侧的 PCAP 异常放进同一安全智能体：用户通过自然语言发起调查，大模型理解上下文并规划动作，本地安全引擎执行检测、形成结构化证据，系统再完成解释、修复或处置建议、复检和报告归档。

## 二、需要解决的问题

1. Prompt 攻击语义伪装强，规则与单一语义模型都存在盲区；
2. PCAP 告警缺少包级定位、行为佐证、攻击链关联和自然语言解释；
3. 普通对话、已有案件追问和新建检测任务容易混路，导致用户必须记住固定关键词；
4. AI 结论若无法回到真实工具证据，就难以审计和复现；
5. 自动化安全处置若缺少授权边界，可能扩大误报影响。

## 三、为什么设计成这样的智能体

### 3.1 对话作为统一入口

Prompt 文本和 PCAP 文件本身都是非结构化安全输入。对话入口允许普通用户说“帮我看看这段内容”或“分析这个抓包”，也允许安全运营人员继续追问“异常在哪个包”“结论可靠吗”“下一步怎么办”。系统通过普通对话、Prompt 检测、PCAP 检测三种路由分流，避免任何可疑文字都被误当成检测任务。

### 3.2 大模型与本地引擎分工

- 大模型负责自然语言理解、案件追问、工具选择、证据解释和下一步建议；
- 本地引擎负责 Prompt 规则与 Entropy-CPD、PCAP 解析与异常检测、证据编号和审计记录；
- 固定策略负责证据融合和处置边界，模型不能虚构 Packet、检测结果或已执行的外部处置。

这种混合架构兼顾了对话体验、检测可重复性和安全审计。模型或知识检索不可用时，基础检测仍可运行，系统只降低语义解释能力，不把降级状态伪装成完整结论。

### 3.3 检测到报告的闭环

平台不是只输出风险标签，而是按“检测 → 解释 → 建议 → 修复/处置 → 复检 → 报告”组织案件。Prompt 可生成修复稿并复检前后差异；PCAP 可继续查看包级证据并关联攻击阶段；所有动作都归档到同一任务中。

## 四、系统实现

### 4.1 Agent 编排与自然对话

`src/agents/agent.py` 使用 LangChain Agent 接入 OpenAI 兼容模型服务。`config/agent_llm_config.json` 登记 11 个核心工具：Prompt 五个、PCAP 四个、知识检索和报告生成。运行时还保留挑战、评测和任务恢复等辅助工作区能力。

消息开头的显式模式标记负责区分 Prompt、PCAP 和普通对话。普通聊天默认直接回答；已有案件追问读取当前任务的消息和证据；只有明确检测、复检、报告等动作才调用安全工具。前端通过 SSE 接收分段回答与工具状态，实现流式呈现。

### 4.2 Prompt 三路检测

`src/tools/prompt_tools.py` 与 `entropy_detector.py` 组合三类证据：

- 规则路：识别已知注入、越权、伪造分隔符和编码特征，输出命中位置；
- 分布路：借鉴公开熵异常与变化点检测研究，以字符级语言统计构造窗口 NLL/熵轨迹，用在线变点检测定位突变候选。这里的理论思想不作为本项目原创声明，项目完成的是面向 Prompt 调查的可运行集成与证据化实现；
- 语义路：调用专用语义模型判断意图和风险类别。

分布候选不会单独“定罪”。语义佐证、分布强度、持续偏移和短文本置信折减共同进入固定融合策略。反事实工具会截断异常位置后的文本重新检测，比较前后分数，验证风险是否确实来自定位片段；若结果不变，则明确标为证据冲突并建议人工研判。

语义模型通常只能给出风险类别和理由，不能稳定指出具体哪个 token 开始异常。本项目把变化点映射为 token/字符区间，在风险轨道上标出异常起点，允许用户查看对应片段、证据编号并进行反事实复核。贡献重点是定位、解释和审计闭环，而不是宣称重新发明 Entropy-CPD 理论。

### 4.3 PCAP 三路分析

`src/tools/pcap_tools.py` 完成文件预检、逐包解析、规则检测、行为检测和证据归并：

- 规则路使用固定阈值和明文载荷特征；
- 行为路使用端口接触广度、连接速率、信标周期性、上行速率、DNS 标签分布等统计信号；
- 融合路归并同类同主体发现，保留来源路线、置信度、时间范围和 Packet 定位。

当前覆盖九类网络攻击候选：端口扫描、SSH 暴力破解、C2 心跳、数据外传、SQL 注入、DNS 隧道、Web 攻击载荷、SYN 洪泛和 ARP 欺骗。0day、加密流量内容解密和完整 APT 渗透链不在已验证覆盖范围。攻击链关联只连接已有证据支持的阶段，不补造缺失环节。

### 4.4 知识、证据、报告与攻防实验

知识检索工具从 Prompt 风险、Token 模型安全、网络与 PCAP、ATT&CK、合规处置等材料中返回佐证。知识内容只用于解释，不能覆盖真实引擎结论。

案件存储记录消息、证据、工具动作和审计事件；证据区分 `real` 与 `derived` 来源。报告工具把案件汇总为结论、证据、限制、建议和授权边界，并生成可归档文件。

Prompt 红蓝实验会生成固定场景并把对抗文本交给同一真实检测管线；PCAP 实验使用固定或参数化教学流量，通过 Packet 证据展示定位与判断过程。实验与用户上传的真实调查分开，避免把教学真值混入真实案件。

## 五、比赛任务逐项对应

### 5.1 基础任务：场景化安全智能体

比赛要求智能体完成真实场景中的安全分析。本项目提供两个场景：

1. Prompt 安全调查：提交文本后完成三路检测、证据解释、修复、复检和报告；
2. PCAP 告警研判：提交抓包后完成预检、解析、异常候选、Packet 定位、攻击链关联和报告。

对应材料为 `src/agents/agent.py`、`src/tools/prompt_tools.py`、`src/tools/pcap_tools.py`、`src/tools/report_tool.py` 及 Web 演示。自然语言入口和案件连续追问体现“智能体”，报告自动生成和告警研判对应比赛示例场景。

### 5.2 进阶任务：领域知识增强与工具扩展

知识增强由 `src/tools/knowledge_tool.py` 和 `assets/knowledge/` 实现，为解释提供领域佐证，并在知识不可用时明确降级。

工具扩展包括自研 Entropy-CPD 分布检测、Prompt 反事实归因、PCAP 行为统计检测、三路消融与攻击链关联。它们均为可执行代码，不是提示词中的能力描述。扩展评测进一步披露了本地信号的准确率和漏检边界。

### 5.3 挑战任务：超级智能体与自主闭环

Agent 能在同一案件上下文中判断“直接回答、追问、建议下一步或调用工具”，并把真实工具结果继续用于解释和报告。Prompt 和 PCAP 双轨共享对话、任务、知识和报告能力，体现跨域协同。

平台展示的是由工具执行记录生成的结构化过程，而非模型自述的隐藏思维链。疑似结果进入人工复核；封禁、隔离、生产替换等高影响动作不由当前检测组件直接执行，从工程上体现“自动化受人控制”。

## 六、扩展测试与可信边界

冻结回归集包含 29 条样本，用于修改后的稳定性回归。补充扩展评测生成 240 条确定性 Prompt 变体，其中攻击与良性各 120 条。本地规则加 Entropy-CPD 的结果为：TP 56、FN 64、FP 0、TN 120，Precision 1.0000、Recall 0.4667、F1 0.6364、FPR 0.0000。

该结果只表示本地规则与分布信号在这批样本上的表现，不包含大模型语义层，因此不能外推为端到端系统准确率。低 Recall 说明未知或未命中固定模式的攻击仍依赖语义模型与人工复核。

PCAP 冒烟测试覆盖 5 个生成式教学文件，共 578 个包，解析错误为 0。正常 Web 流量也产生 1 项 C2 候选，说明周期性或加密流量可能触发行为误报，必须由分析人员结合上下文复核。

## 七、总结与后续计划

StreamLens 明鉴的核心价值不是“让模型替代分析人员”，而是把自然语言理解、可重复检测、证据解释和人类授权放进同一个案件闭环。项目已经具备 Prompt 与 PCAP 双轨调查、流式对话、证据归档、攻防实验和报告能力。

后续将扩充盲测样本和真实授权数据，补齐按攻击族的端到端语义评测；优化 PCAP 行为阈值和困难负样本；完善 HTTPS、认证、限流及外部安全设备的授权接口。所有新增能力仍需通过真实工具记录和测试结果证明。

## 附：口语化介绍

StreamLens 明鉴可以理解成一个既懂大模型 Prompt、又会看网络抓包的安全助手。你把可疑文字或 PCAP 文件交给它，它不会只甩给你一个“有风险”的标签，而是先调用真实检测工具，再告诉你问题在哪里、证据是什么、结论有多确定、下一步怎么做。

比赛的基础任务，我们用 Prompt 调查、PCAP 告警研判和报告生成来完成；进阶任务，我们用安全知识检索、Entropy-CPD、反事实归因和 PCAP 行为检测来完成；挑战任务，我们用会规划工具的 Agent、跨两类数据的案件上下文、可审计证据和人工授权边界来完成。

我们也不会把小样本结果说成“什么攻击都能检出”。扩展测试显示本地信号误报低，但仍会漏掉部分没有固定模式的攻击；正常周期性流量也可能被判成 C2 候选。这些限制被直接写进报告，因为一个可信的安全智能体不仅要能发现问题，也要知道自己什么时候不能下结论。
